# RQLens refactoring review — 2026-10-10

Baseline: `bf10b6e`, initially clean. This is an incremental, API-preserving pass
on an already small framework, not a claim that every quality signal improves.

## Findings and changes

1. **Hidden payload copies in protocol wrappers** (`shelllist-daemon-core`,
   `envelope.rs`, `jsonl_wire.rs`). `json!` serializes a supplied `Value` by
   reference, rebuilding its contents. Success, error, JSONL response and event
   wrappers now insert owned payloads directly. Optional error fields use the
   map's existing iterator extension API. A regression checks string allocation
   identity at each wrapping stage, as well as its contents. Public signatures,
   wire fields and optional-field omission are unchanged.
2. **Unnecessary intermediate JSON trees** (`shelllist-hyprland/work_area.rs`).
   The five-document batch now deserializes monitors, workspaces, rules and
   clients directly into their destination types, without a vector of complete
   JSON trees and a second conversion pass. The size bound remains; `end()`
   rejects trailing documents/data. Regressions cover missing/extra documents
   and malformed selectors. Known duplicate struct fields are now rejected
   rather than silently taking the last JSON-map value; a regression records
   this stricter malformed-input behavior. Error text/order may also change.
3. **Avoidable D-Bus string allocations** (`shelllist-daemon-tokio/owner.rs`).
   Both owner-change readers borrow the three signal fields. Only a selected
   unique-name loss is copied into the owned broadcast notification; unrelated
   signals and well-known-name replacement checks need no string copies.
   Existing isolated real-bus tests pass with the borrowed decoding.
4. **Repeated traversal and output policy** (`shelllist-local-build`). Graph
   capture and preflight share `policy::direct_inputs`, retaining their existing
   follows-edge semantics and their distinct error-handling policies. CLI JSON
   output shares one serializer/printer; CLI tests share their parser setup.
   Symlink resolution handles parent/current components before link inspection,
   removing one nesting level without changing traversal order or confinement.
5. **Redundant control flow** (`output_actor.rs`, `jsonl.rs`, `work_area.rs`).
   Failed ID-query sends drop their oneshot sender, so the existing receive
   fallback handles both channel failures; a closed-actor regression covers it.
   Forced call draining uses Tokio's `JoinSet::shutdown` instead of repeating
   its abort-and-join loop. Selector dispatch consumes its existing string slice
   directly: its wildcard arm already rejects empty/multicharacter/Unicode
   kinds, so separate byte-width validation/conversion was redundant. Relative
   monitor selection uses `rem_euclid`; numeric IDs use checked conversion.
6. **Repeated test setup** (`work_area_tests.rs`). More selector assertions use
   the existing `assert_rule` helper instead of rebuilding identical zero-gap
   rules. This removes one token-clone group without removing assertions or
   creating a cross-crate test abstraction.

No dependencies, public APIs, lint suppressions or unsafe code were added.
No public API was deleted merely because this workspace has no local caller.
Private dead-code linting passes; the reduction here is redundant control flow
and copying, not an invented inventory of removable public APIs.

Graph traversal cognitive/cyclomatic complexity falls from **6/11 to 4/10**;
preflight traversal from **7/9 to 5/8**; monitor matching from **7/8 to 6/7**.
The direct batch parser's Halstead observation falls from **31,341.50 to
25,214.19**, while its cyclomatic count rises from 7 to 8 with the explicit
end-of-input check. Flattening symlink resolution reduces nesting but increases
its Halstead observation. These trade-offs are not hidden in the totals.

**Architecture caveat:** production module boundaries are unchanged. Shared
traversal/output helpers and reuse of Tokio's shutdown operation reduce local
implementation duplication. The numerical leverage increase and extra graph
edge come from the new envelope-to-JSONL ownership regression, not increased
production reuse. Locality is already near its ceiling and does not improve.
The remaining clone findings are short error-display implementations and test
fragments; they do not justify a new generic error/test framework.

Production scope excludes function names with a `tests` module, files ending
in `_tests.rs`, and integration-test paths. This is an authored-syntax naming
heuristic, not compiler/cfg analysis. Halstead observations describe syntax,
not developer hours; their sum is not a whole-program effort estimate.
Allocation improvements follow from ownership and pointer-identity assertions,
not a throughput or peak-memory benchmark. No new benchmark is claimed.

## Validation and the stale-target finding

- **Fresh baseline:** 90 tests passed; one existing live Hyprland probe ignored.
- **Fresh final build:** 92 tests passed; the same probe ignored. Doctests pass.
- Fresh workspace/all-target Clippy with `-D warnings`, formatting, rustdoc with
  `-D warnings`, and `git diff --check` pass.
- Consumer suites, live compositor probes, deployments and service restarts were
  not run. Coverage and runtime performance were not measured.

The first checks against the existing `target/debug` were **discarded**:
Cargo considered old binaries fresh, but their binary dependency metadata
referenced `quality-commit-sequence/tree/...`, an earlier review snapshot.
Those binaries did not contain the new tests. Final validation uses a separate
fresh target, and its logs confirm execution of both new regression tests.
Baseline tests were independently rebuilt from a `git archive HEAD` snapshot
with another fresh target. Avoid sharing a Cargo target between snapshot roots.

The declared/pinned Rust 1.85/1.85.0 compatibility issue remains pre-existing;
this pass uses Rust/Cargo 1.95 and does **not** establish MSRV compliance.
