# RQLens refactoring review — 2026-10-13

Baseline: `aa83187`, initially clean. Incremental, API-preserving review of the
four-crate workspace using the locally installed source-checkout executable at
`../rust-quality-lens/target/debug/rqlens` (the checkout is not named
`rustqualitylens`). No dependencies, unsafe code or lint suppressions added.

## Findings and changes

1. **Nested framing/allocation policy** (`shelllist-daemon-tokio/jsonl_input.rs`).
   Separate bounded buffer extension from asynchronous record framing. The helper
   retains geometric allocation growth, the hard ceiling, prefix discard on
   overflow and cancellation-safe state. The framer is now a child of its sole
   consumer, `jsonl`, with parent-only visibility rather than crate-wide access.
   Expand the existing boundary matrix to limits 0, 1 and 8 and bare CR at EOF;
   split UTF-8, CRLF, oversized draining and cancellation tests remain.
2. **Dead private compatibility plumbing** (`jsonl.rs`). Remove the ignored
   failure mapper and method arguments from the internal execution chain.
   Public `CallFailure`, `CallFailureMapper` and the config field remain: sibling
   app, bar, Bluetooth, clipboard and NetworkManager clients still reference
   them. Document explicitly that the field is ignored. Consolidate response
   error conversion and ordinary uncertain-outcome construction; use Tokio's
   `watch::Receiver::wait_for` instead of a manual readiness loop.
3. **Nested reconnect error handling** (`shelllist-hyprland/lib.rs`). Separate
   receiver-closure cancellation from reconnect policy, propagating send failures
   through the reconnect future instead of nested returns. Preserve deduplicated
   connection failures, EOF backoff and cancellation during all phases. Remove
   the private discovery function's impossible error result; signature validation,
   peer checks and connection failures remain fallible.
4. **Payload copying** (`jsonl.rs`). Deserialize event JSON as a borrowed `&str`
   from the D-Bus body; only the stream name needs ownership for actor delivery.
   This avoids an intermediate payload-sized string allocation before JSON
   parsing. The existing isolated-bus directed-signal test now exercises this
   borrowed decoding shape. Malformed JSON still uses the existing raw wrapper.
5. **Duplicated test transport scaffolding** (`output_actor.rs`, JSONL tests).
   One actor-owned, test-only fixture handles the bounded duplex writer, JSON
   reads, task joining and unexpected-output check for six tests. Assertions
   remain, and overload/late-subscription tests now also reject extra records.
   Replace both test wildcard imports with explicit owning-module imports.

Framing cognitive/cyclomatic complexity falls from **20/10 to 12/8**; its new
bounded-extension helper contributes **2/3**. Request execution falls from
**5/11 to 3/9**. Reconnection's old **13/7** becomes **6/7**, with a **0/1**
cancellation wrapper. Extraction adds function baselines, so aggregate cyclomatic
improvement is small; the maximum remains a legitimate selector dispatch.

Locality's numerical score does **not** improve. Narrowing framer visibility is
an enforceable ownership improvement; sharing the actor fixture improves reuse,
but the leverage increase is test-related, not evidence of increased production
reuse. Using Tokio's readiness operation removes production implementation code.
The remaining AST clone is short error-display boilerplate, not justification
for a generic error framework. Necessary ownership/Arc clones remain. The
allocation reduction above is not a reduction in explicit clone-call count or a
measured throughput/memory result. Net Rust LOC reduction is deliberately modest.

Production scope excludes `tests`, `deadline_tests` and `test_support` qualified
names, `*_tests.rs`, and integration-test paths. This is an authored-syntax
heuristic, not compiler/cfg analysis. Halstead observations describe syntax,
not developer hours; their sum is not a whole-program effort estimate.

## Validation and limits

- Fresh, dedicated Cargo target: **115 tests passed**, both before and after;
  two existing tests remain ignored (live compositor and manual cost sample).
- Formatting, workspace/all-target Clippy with `-D warnings`, doctests, rustdoc
  with `-D warnings`, and `git diff --check` pass.
- Rust/Cargo 1.95 used. The manifest still declares 1.85 despite pre-existing
  newer syntax; MSRV compliance was not established or changed in this pass.
- Consumer source references were inspected, but consumer builds, deployments,
  live compositor probes, coverage and performance benchmarks were not run.
- RQLens evidence remains **partial**: the fingerprint reports an incomplete
  Cargo project/helper dependency graph. Semantic unresolved references increase
  from 46 to 50; architecture scores are heuristic observations, not verified
  gates. All 42 Rust files parsed in both captures. Production finding counts
  are observations, not proof of absence of every panic or escape path.
